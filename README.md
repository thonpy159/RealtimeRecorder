# リアルタイムレコーダー

本アプリのソースコードは [MIT License](LICENSE) で公開しています。
同梱ライブラリ・モデルにはそれぞれのライセンスが適用されます。
出典と条件は [第三者ソフトウェアの案内](packaging/THIRD_PARTY.txt) を参照してください。

Windows 11上で動く、日本語のローカル文字起こしアプリです。マイクを「自分」、WASAPI Loopbackで取得する再生音声を「相手」として表示します。Google Meetの拡張機能やクラウド音声認識APIは使いません。3人以上の会議では再生側の全員が「相手」になります。

音声はメモリで処理して認識後に破棄します。通常利用中の音声ファイル保存・外部送信・文字起こしの自動保存はありません。保存ボタンを押した場合だけMarkdownを作成します。ソースからの初回セットアップには、依存ライブラリとモデル取得のためインターネット接続が必要です。配布版には必要なモデルを同梱しています。

## 対象環境

- Windows 11 x64（配布版はPython不要。ソースからの実行はPython 3.11 x64）
- Ryzen 5 / RAM 16GBを想定。GPU不要
- ASR: ReazonSpeech k2-v2 INT8（日本語） / sherpa-onnx CPU、初期値2スレッド
- VAD: Silero ONNX。発話が確定した後に認識します。一文字ずつの逐次字幕ではありません。

## 配布版の起動（Python不要）

[Windows版ZIPをダウンロード（約201MB）](https://github.com/thonpy159/RealtimeRecorder/releases/latest/download/RealtimeRecorder-Windows-x64.zip)

ダウンロードした `RealtimeRecorder-Windows-x64.zip` を、書き込みできるフォルダへすべて展開して
`RealtimeRecorder.exe` をダブルクリックします。コマンドプロンプトは表示されません。
exeと同じ場所にある `_internal` と `models` が必要です。exeだけを移動しないでください。
[リリース情報・チェックサム](https://github.com/thonpy159/RealtimeRecorder/releases/latest)も確認できます。

配布版はReazonSpeechとSilero VADを同梱し、起動時のモデルダウンロードは不要です。
比較用モデルは含みません。開発用ソースからの起動には、以下のセットアップ後に `run.bat` を使います。

配布版の作成方法は [packaging/BUILD.md](packaging/BUILD.md) を参照してください。

起動後、モデルの読み込みが終わると「開始できます」になります。開始を押すまでは音声を取得しません。

## 初回セットアップ・再セットアップ

PowerShellで次を実行します。

```powershell
git clone https://github.com/thonpy159/RealtimeRecorder.git
cd RealtimeRecorder
.\setup.ps1
```

実行ポリシーによりスクリプトがブロックされる場合は、この実行に限定して次を使用できます。システム全体のポリシーは変更しません。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

setup.ps1は、プロジェクト直下の `.venv` のみを作成・利用し、依存関係、モデル、import、pytest、モデル実ロードと公開テスト音声の認識を確認します。プロジェクト外の仮想環境は使用・変更しません。正常でないプロジェクト内の仮想環境はバックアップ名に変更します。

Pythonが `py -0p` に登録されていない場合に備え、setup.ps1には `%LOCALAPPDATA%\Programs\Python\Python311\python.exe` の検出も用意しています。グローバルPythonは仮想環境の作成にだけ使用します。インストール先は必ず本プロジェクトの `.venv` です。実際に検証したバージョンは `requirements-lock.txt` に固定しています。

標準のReazonSpeechに加え、比較用のSenseVoice・Whisper small・Kotobaも取得します。初回の合計ダウンロードは数GBあり、回線速度により時間がかかります。必要なINT8ファイルと公開テストwavだけを展開し、アーカイブは削除します。取得途中の `.part` ファイルから再開でき、サイズと展開エラーを検査します。以降はローカルのSHA-256マニフェストで不足・破損を検出します。

## マイクの確認

左側の「マイクをテストする（8秒）」を押し、短い文を話してください。8秒後に自動停止し、左側に認識結果を表示します。テスト中はマイクだけを取得し、会議の文字起こし欄には追加しません。音声ファイルは作りません。

音が小さいときの補正と、左右チャンネルの位相反転で声が消える問題への対策を実装しています。ただし元の入力が無音・雑音だけの場合、増幅しても言葉は復元できません。実際の声の認識が正しいことをここで確認してください。

## Google Meetでの使い方

1. イヤホンまたはヘッドホンを接続します。スピーカーで相手の声を出すとマイクにも入り、「自分」と「相手」に二重認識されるためです。
2. Meetのマイクとスピーカーを確認します。アプリも同じ物理デバイスを選びます。
3. 「マイク（自分）」は通常「Windowsの既定マイク」で構いません。明示選択する場合は使用するWASAPIマイクを選んでください。番号は接続状況で変わります。
4. 「相手音声（Loopback）」は通常「Windowsの既定再生デバイス」です。Meetが別の出力先を使っている場合は、その出力に対応する `[Loopback]` を選びます。
5. 「開始できます」になったら「文字起こしを開始」を押します。自分・相手それぞれの音量メーターと「発話中」表示を確認します。
6. 約800msの無音で発話を確定し、順番に認識します。会話表示は認識の完了順ではなく発話開始時刻で並びます。
7. 終了時は「停止」を押し、残りの発話の認識が終わって「停止中」になるまで待ちます。その後「Markdown保存」で保存してください。

LoopbackはMeet以外の同じ出力先に流れる通知音・動画・音楽なども取得します。面談中は不要な再生を止めてください。AIによる話者分離ではなく、入力経路による「自分／相手」の区別です。

## 画面と保存

- **停止**: 両方の音声取得を止め、VADに残った発話と認識待ちキューを処理します。モデルは保持するため、再開時に巨大モデルを読み直しません。
- **全文コピー**: 時刻・話者つきの全文をクリップボードへコピーします。
- **Markdown保存**: UTF-8の `.md` に保存します。保存先を指定できます。
- **クリア**: 確認後、表示中の文字起こしを消します。録音中の未確定発話や認識待ちはその後追加されることがあります。完全に区切るには先に停止してください。
- **自動スクロール**: 最下部にいるときだけ新しい内容へ追従します。上へスクロールすると位置を保持し、最下部へ戻ると追従を再開します。
- **閉じる**: 取得を停止し、処理待ちとワーカーを終了してから閉じます。未保存の表示がある場合は確認します。確実に保存するには「停止→保存→閉じる」の順で操作してください。

## 設定と用語辞書

同梱の `config.json` を編集して設定を変更します。アプリを終了してから、exeと同じフォルダ（ソース版ではプロジェクト直下）のファイルをメモ帳などで開き、値を変更してUTF-8で保存し、アプリを起動してください。

初期内容は以下のとおりです。`dictionary` の左側が置換前、右側が表示したい表記です。不要な項目は削除でき、置換しない場合は `{}` にします。JSONの最後の項目にはカンマを付けないでください。ファイルを削除した場合は既定値で再作成します。破損した設定は上書きせず、画面にエラーを表示します。

```json
{
  "asr_threads": 2,
  "asr_engine": "reazon",
  "vad": {
    "threshold": 0.35,
    "silence_ms": 800,
    "min_speech_ms": 180,
    "pre_roll_ms": 500,
    "post_roll_ms": 200,
    "max_speech_s": 20
  },
  "dictionary": {
    "エーアイ": "AI",
    "エスエヌエス": "SNS",
    "ユーアールエル": "URL",
    "ユーチューブ": "YouTube",
    "グーグル": "Google"
  },
  "ui": {"font_size": 14, "auto_scroll": true},
  "asr_queue_size": 32
}
```

用語辞書は文章内を置換します。長いキーを優先し、一回だけ置換するため連鎖置換しません。元の `raw_text` と表示用 `display_text` は別々に保持します。誤変換しやすい単語は、必要に応じて辞書から削除してください。

CPUスレッド数は1・2・4から選べます。画面で変更すると設定を保存し、**次回起動時**に適用します。起動中はモデルを一度だけロードするため、録音の開始・停止や設定変更では再ロードしません。

VADは2入力で独立しています。16kHz mono float32への変換には状態を維持するsoxrの帯域制限リサンプラを使います。500msの履歴と200msの後続音声を付け、長い発話は約20秒ごとに確定します。sherpa-onnx側にも開始補正があるため、実際の先行音声量には若干の幅があります。

## 認識エンジンとモデル

標準はReazonSpeech k2-v2 INT8、CPU 2スレッドです。2026-09-24に、人が話した公開日本語音声120本（選定32本・確認88本）と、2入力同時の実時間GUI表示で再評価しました。合成音声だけで選んだSenseVoiceから変更し、9月18日に修正したマイク処理とUIは維持しています。

今回の測定値と制限は [日本語実音声の検証記録](VERIFICATION-JAPANESE.md) を参照してください。本人の話し方に合わせる設定や、正解文への特別な置換は使っていません。認識精度は音質・発話内容で変わり、句読点はSenseVoiceより少なくなります。

「詳細設定」からSenseVoice・Whisper small・Kotobaにも変更できます。変更は次回起動時に反映されます。KotobaはこのPCでは即時表示に合わない処理時間でした。モデルは同時に複数ロードしません。Whisperもローカルファイルだけを使います。

- [SenseVoice公式モデル説明](https://k2-fsa.github.io/sherpa/onnx/sense-voice/index.html)
- [Whisper small変換モデル](https://huggingface.co/Systran/faster-whisper-small)
- [Kotoba変換モデル](https://huggingface.co/kotoba-tech/kotoba-whisper-v2.0-faster)

標準ReazonSpeechは以下のファイルです。

公式sherpa-onnxリリースから取得します。

- [ReazonSpeechモデルの公式説明](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/offline-transducer/zipformer-transducer-models.html)
- [公式モデルリリース](https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models)
- [Silero VADの公式説明](https://k2-fsa.github.io/sherpa/onnx/vad/silero-vad.html)

使用するフォルダは `models/sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01/` です。

- `tokens.txt`
- `encoder-epoch-99-avg-1.int8.onnx`
- `decoder-epoch-99-avg-1.onnx`
- `joiner-epoch-99-avg-1.int8.onnx`

VADは `models/silero_vad.onnx` を使います。モデル・仮想環境・ログはGit除外対象です。

## トラブルシューティング

### 相手の声が認識されない

1. Meetのスピーカー設定とアプリのLoopbackが同じデバイスか確認します。「Windowsの既定」とMeetの個別指定が違う場合があります。
2. 相手が話しているときに「相手」の音量メーターが動くか確認します。
3. 動かない場合は「停止→デバイス一覧を更新→正しいLoopbackを選択→開始」と操作します。
4. メーターは動くが認識されない場合は、再生音量が小さすぎないか、発話が短すぎないか確認します。

無音時にも正しく発話確定するため、選択した再生先にはゼロ値の無音ストリームを開きます。可聴音を加えたり音声を保存したりするものではありません。

### マイクが開始できない／メーターが動かない

既定マイクはWASAPIを使用します。MME/DirectSoundで列挙された古い互換デバイスは、環境によって開始できないことがあります。既定マイクまたはWASAPIのRealtekマイクを選んでください。Windowsのマイクへのアクセス許可、ミュート、他ソフトの排他利用も確認してください。

### Bluetoothやイヤホンを切断した

取得エラーは画面に表示し、両入力を安全に停止します。接続し直して一覧を更新し、選び直して開始してください。録音中の自動切替は行いません。Meetの出力先を途中で変更した場合も、アプリ側を停止して選び直してください。

### モデル不足・破損／ダウンロード失敗

`setup.ps1` を再実行してください。既存の完全なモデルはSHA-256で検査して再利用します。接続不良は途中から再開します。破損したアーカイブを検出した場合は除去してエラー終了するため、回線を確認してもう一度実行してください。

### 認識が遅い

CPU設定はまず2のまま、不要な高負荷アプリを止めて確認します。ログの `RTF` が継続して1を超えると、会話速度より認識が遅く待ち時間が増えます。認識待ちが上限に達すると、無制限にメモリを増やさず取得を停止して残りを処理します。停止処理は待ちキューの量により時間がかかります。

### 設定やMarkdownを保存できない

書き込み権限・保存先・空き容量を確認してください。設定ファイルが壊れている場合、元のファイルを保持して内容を修正するか別名に変更し、再起動して既定設定を生成します。

### ログ・診断

通常ログは `logs/app.log` に出力し、サイズでローテーションします。デバイス名、例外、処理時間等を記録し、会話全文や音声そのものは通常ログへ出しません。

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts\diagnose.py
.\run.bat --smoke-test
```

`diagnose.py` は公開テスト音声1.wavだけを認識し、`logs/diagnostic.json` に結果と実測値を保存します。`--smoke-test` は実マイク・Loopbackを約6秒ずつ2回取得し、開始・停止とワーカー終了を確認して自動終了します。音声や会話全文を保存しません。通常は引数なしで起動してください。

`scripts/loopback_e2e.py` は公開テスト音声を現在の既定再生先に流し、実際のLoopback経路を確認する開発用診断です。同じ再生先の他アプリの音声も混ざるため、使用時はほかの再生を止めてください。レポートには認識文字数と性能だけを残します。

## 検証結果と制限

配布exeで公開日本語音声の認識・画面表示・正常終了を確認しています。発話後1～3秒は目標値です。CPU負荷、同時発話による待ち、音量や音質によって変わり、Meetと同時利用した性能は最後に実会議で確認してください。

実際のBluetooth切断やWindowsシャットダウンは、この作業では強制的に発生させていません。切断相当の例外・開始失敗・停止時の残音処理は自動テストで確認しています。会話はメモリだけに保持するため、OSによる強制終了や停電時には未保存テキストは残りません。

## ソース内の開発用ファイル

`tests/` は設定・音声処理・画面操作の不具合を確認する自動テストです。`scripts/` も開発・再検証用として保持しています。これらのテスト一式、比較用音声・モデル、キャッシュ、ログは利用者向け配布ZIPに含めません。

ソース版で `config.json` を自分用に変更した場合、その変更を公開コミットに含めないでください。配布ビルドは個人設定をコピーせず、アプリの既定値から初期設定を生成します。
